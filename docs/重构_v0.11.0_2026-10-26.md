## 2. 设计说明（接手要点）

1. **tbuf 是唯一内存状态源**：`recentTranscript()`（AI 快答）、半句修正锚点（`lastCommitted`/`lastCommittedWasClosed`）、精修替换定位（`lastCommittedLineId`）都走它。所有方法 synchronized——历史上主线程专属调用零成本，跨线程也安全。
2. **行 id 生命周期**：`pushRecent` 分配 id → `recordCommitted(text, closed, id)` 绑定到提交句 → 半句修正/精修替换 `updateLastCommitted`（**id 不变**）→ 按改写文本。id 找不到（行被 600 容量滑窗挤出）时 `replaceRecentText` 返回 false，服务退回 `replaceRecentSuffix`。
3. **磁盘单写者**：主线程只 `runOnTranscriptWorker` 入队；`transcriptFile`/`lastLineInfo` 仅 worker 线程读写。懒建文件在 worker 任务开头 `createTranscriptFileIfNeeded()`（同队列天然先于一切写），**零语句会话仍不产生文件**（对齐旧行为）。
4. **O(1) 末行替换**：追加时记录行首字节偏移（UTF-8 字节，非字符）；替换若目标恰为末行（含时间戳前缀整体匹配）→ seek 覆写 + `setLength` 截断；慢路径（全量扫描）执行后 `lastLineInfo = null` 失效，下次追加重建。
5. **停止轮询条件扩展**：`refineBusy == false && 精修队列空 && pendingTranscriptOps == 0`（或 30s 硬上限）才 stopSelf——`onDestroy.shutdownNow` 现在也不可能丢转录尾部写任务。`transcriptExecutor.shutdownNow()` 已加入 onDestroy（系统强杀路径的兜底）。
6. **行为变化（唯一）**：无。接口、广播、文件格式全部不变。
