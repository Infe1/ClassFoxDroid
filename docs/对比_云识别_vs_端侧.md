# 对照报告：手机录音（云）识别 vs 端侧离线识别

> 基准：`D:\downloads\"标准录音 53"-转文本结果.txt`（手机/云端识别，约逐字）
> 待测：`mp3/标准录音 53.mp3` → 16kHz 单声道 → 3 段切片 → 端侧自检（sherpa-onnx streaming zipformer zh-int8-2025-06-30，encoder 153MB）
> 结论先行：**端侧能保住课堂的"骨架"（谁在讲、讲哪块、关键词），字级准确率与云差距明显；用于实时字幕 + 关键词警报（点名/作业/考试）是够用的，用于逐字稿不行。**

## 段1：课程介绍（00:29–01:35）

**云稿**：
> 那么这学期呢由我来给大家咱们班同学呢讲这个心理学的这门课。那么在介绍这门课的具体之前呢，我们先把这个有一些相关的一些信息给大家介绍的。啊我们这门课的这个理论课和实验课的课程安排……基本上都没有你们这个早八的课了。所以呢我们有一个要求，就是上课的时候，上课铃响之后……不能再进教室。

**端侧**：
> 贡献上那么这个阶段由我来给大家问题的话讲这个事情要是免责 那么在注销路之前的处理之前呢我们先把这个有一些相关的一些信息给他介绍来哈我们这堂课的这个评论课我实际上他这个不同安排 …… 基本上没有你们这个早上的课所以呢我们有一个要求就是上课的时候上课离散了之后……就会再进入教室

**评**：骨架全在（由我来讲这门课 / 先介绍相关信息 / 理论课安排 / 没有早八 / 上课铃响后不能进教室），字面错乱多（"心理学→事情要是免责"、"铃响→离散"）。**关键词警报不受影响**。

## 段2：指针复习（40:10–41:32）

**云稿**：
> 因为指针的引用作用非常多……包括我们接下来要讲链式结构，也要练习链式结构，要用到大量的指针的，如果指针的概念不清晰的话，那么就拜托大家……好，那我们看一下这里面，这里面实际上这个呢是从我们这个地址里面取出它的值……那还是快速的过一遍啊，因为指针在函数的调用里面用的比较多……就是让大家写一个函数……传入两个整形的参数，然后交换。

**端侧**：
> 啊稍微我们接下来要产生的这些更关键性的结构的话……那么这个概率就是大家就是摸无标的……你们回去赶紧开车复习一下好不好 好那我们看一下这里面这里边其实这个呢是从我们这个呃直接的地址一块儿去负责提供 …… 那么就是快速因为车正在进行 …… 是特别让大家写一个……还是我们希望常有两个整形的参数然后交换

**评**：关键动作（接下来要讲的结构 / 回去复习 / 看地址取值 / 快速过一遍 / 写交换函数两个整形参数）均有命中，但专业词大面积错（链式结构→更关键性的结构）。**本段警报词"作业/下节课"级别的内容在端侧仍可命中，但更细的概念词会漏。**

## 段3：绪论结尾（1:28:30–1:29:47）——三段中最好

**云稿**：
> 那么这里面就谈到数据的操作……是对现实问题的一个抽象。那么这个实现的时候呢，它实际上是建立在特定的存储结构之上的。就我们刚才说你是线性结构，你是定义在顺序存储上的……它一定依赖于计算机的具体的程序……

**端侧**：
> 我们是不是针对一个角度来说会显实的问题的一个抽象那么这个实现的时候它是让人建立在特定的进行结构之上就我们刚才说你是清明节你是定义在啊甚至上的他的折叠的基础上那具体地实现方法是不一样的它一定依赖于计算机……

**评**：核心概念链（现实问题→抽象→实现→建立在特定存储结构之上→依赖于计算机）基本可读，仅专业词错（线性结构→进行结构/清明节，顺序存储→啊甚至）。**这段质量已接近可用笔记的下限。**

## 量化估计

| 维度 | 云识别 | 端侧（153MB 流式） |
|---|---|---|
| 字错率（主观估计） | <5% | 约 40–55%（段3最好，段1最差） |
| 主题/话题跟踪 | 逐字 | 可用（骨架保留） |
| 关键词警报（点名/作业/考试/下节课） | 可用 | **可用**（高频实词命中率高） |
| 逐字稿/笔记 | 可用 | 不可用，需二次润色或换模型 |

## 改进路线（按性价比）

1. **文件转写用非流式 Paraformer 大模型**（端侧离线，精度接近云识别）：设置里加"录音文件高精度转写"，实时链路维持现状——不增加实时延迟，仅转写文件时用大模型。
2. 实时链路升格：云+端双通道（端侧实时字幕保底，可配置云端二次精修）——需要网络与 API Key，做成可选项。
3. 关键词警报词表可加入课堂高频误识别形态（如同音词），代价小。
